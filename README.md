# TeamGrid

## Локальный запуск на этом компьютере

Из PowerShell в папке проекта:

```powershell
.\start.cmd
```

Или из Ubuntu/WSL:

```bash
cd ~/teamgrid
bash scripts/start-local.sh
```

Открыть http://localhost:3000/teamgrid/. Остановка — Ctrl+C в терминале запуска.

Локальный аккаунт: `admin@example.com`, пароль `TeamGridLocal2026!`. Это отдельная локальная база
`teamgrid_local`; данные сохраняются между запусками. PostgreSQL установлен в Ubuntu и запускается
автоматически вместе с WSL.

Launcher использует Linux Node.js, устанавливает зависимости при изменении package.json или
package-lock.json, генерирует Prisma Client и применяет миграции. Локальный аккаунт создаётся только
в пустой базе; существующие данные не очищаются. Не используйте `npm run db:seed` для обычного
запуска: штатный seed очищает таблицы.

В `.env` настроены `DATABASE_URL`, `JWT_SECRET`, `EMAIL_VERIFICATION_SECRET` и `TEAMGRID_LOCAL=1`.
Файл с секретами не хранится в Git. При `TEAMGRID_LOCAL=1` и `NODE_ENV=development` письма с кодами
подтверждения выводятся в терминал сервера. В production требуется настоящий SMTP; локальный режим
там не применяется.

Эта настройка окружения уже выполнена на текущем компьютере. На новой машине нужны Linux Node.js
22.22.2+ (ветка 22), npm из `packageManager`, PostgreSQL и отдельная база `teamgrid_local` с
собственным `.env`. Launcher не устанавливает системные пакеты.

**TeamGrid** — веб-приложение для управления графиком смен сотрудников.

Система предназначена для компаний, где сотрудники работают по сменному графику. Она позволяет
администраторам формировать расписание, а сотрудникам — удобно просматривать свои смены и отправлять
заявки на изменение графика.

## Возможности

### Для сотрудников

- Просмотр личного графика смен.
- Просмотр расписания по дням.
- Удобная мобильная версия с лентой дней.
- Просмотр информации о своей смене.
- Отправка заявок на изменение графика.
- Отслеживание статуса отправленных заявок.

### Для администратора

- Просмотр графика сотрудников.
- Назначение смен сотрудникам.
- Создание и редактирование расписания.
- Изменение уже назначенных смен.
- Управление сотрудниками.
- Просмотр заявок на изменение графика.
- Подтверждение или отклонение заявок сотрудников.
- Централизованное управление расписанием команды.

## Основная концепция

TeamGrid разделяет работу с расписанием на две стороны:

```text
                    TeamGrid
                       │
             ┌─────────┴─────────┐
             │                   │
        Сотрудник            Администратор
             │                   │
       ┌─────┴─────┐       ┌─────┴──────────┐
       │           │       │                │
    График       Заявки   График         Управление
       │           │       │                │
   Просмотр    Изменение  Создание       Сотрудники
                            │             Заявки
                         Редактирование
```

Сотрудник не изменяет расписание напрямую. Вместо этого он отправляет заявку, которую рассматривает
администратор.

Это позволяет сохранить единый источник актуального расписания и избежать случайных изменений.

## Интерфейс

Главный принцип интерфейса — **простота и ориентация на функциональность**.

### Desktop

На больших экранах расписание может отображаться в виде полноценной сетки:

- сотрудники;
- даты;
- назначенные смены;
- дополнительные состояния;
- действия администратора.

### Mobile

На мобильных устройствах расписание адаптируется под небольшой экран.

Основной формат — **лента дней**, позволяющая быстро переключаться между датами и просматривать
назначенную смену.

## Роли

В системе предусмотрено разделение прав доступа.

### Employee

Обычный сотрудник:

- просмотр собственного расписания;
- просмотр информации о сменах;
- создание заявок;
- просмотр статуса заявок.

### Admin

Администратор:

- управление расписанием;
- управление сотрудниками;
- редактирование смен;
- обработка заявок;
- доступ к административной части приложения.

## Заявки на изменение графика

Одна из ключевых функций TeamGrid — система заявок.

Пример сценария:

```text
Сотрудник
    │
    │ Создаёт заявку
    ▼
┌───────────────┐
│    Заявка     │
│ на изменение  │
│    графика    │
└───────┬───────┘
        │
        ▼
   Администратор
        │
   ┌────┴────┐
   │         │
Одобрить   Отклонить
   │         │
   ▼         ▼
График     Без изменений
обновлён
```

Это позволяет сотрудникам самостоятельно инициировать изменения, сохраняя контроль расписания за
администрацией.

## Цель проекта

TeamGrid решает простую практическую задачу — **сделать управление сменным графиком удобным как для
сотрудников, так и для руководителей**.

Вместо таблиц, сообщений и ручного согласования в разных местах вся информация о расписании и
изменениях находится в одном приложении.

## Основные принципы

- **Простота** — интерфейс не перегружен лишними элементами.
- **Удобство** — расписание должно быть понятно с первого взгляда.
- **Мобильность** — приложение удобно использовать со смартфона.
- **Контроль** — изменения графика проходят через администратора.
- **Централизация** — актуальное расписание хранится в одном месте.
